# Decision log

| # | Date | Decision | Options considered | Rationale |
|---|---|---|---|---|
| D1 | 2026-11-07 | Commit straight to `main` during early stages | PR per stage; direct to main | Agreed with the team. Nobody else is contributing yet. |
| D2 | 2026-11-07 | Python 3.11 via `uv`; deps pinned in `requirements.txt` compiled from `requirements.in` | Poetry; conda; plain pip freeze | uv is fast, installs Python itself and produces a plain pinned requirements file that anyone can read. |
| D3 | 2026-11-07 | R 4.1.2 from Ubuntu 22.04 apt; R packages from `r-cran-*` apt packages, listed in `r/packages.txt` | renv lockfile; rig + CRAN snapshot | The distro pins the versions, so dev VM and CI (ubuntu-22.04) match. We keep R dependencies minimal (base `glm` + `jsonlite`) so the R→Python translation stays explainable. |
| D4 | 2026-11-07 | Model card is JSON validated by JSON Schema (`schema_version` 1.0.0), not YAML | YAML + schema; pydantic models | JSON maps directly to Python dicts and JSON Schema. It has no extra parsing rules and is easy to show in the UI. |
| D5 | 2026-11-07 | Gate audit log is an append-only JSONL file; gate status is derived from it | DB table; status field on the card | Simple and tamper-evident enough for a hackathon. The UI and CLI share one writer function. |
| D6 | 2026-11-07 | Orchestrator is resumable: each `make run` advances until the next pending gate | Long-running process polling for approvals; Airflow/Prefect | Easiest to explain. One command covers both CLI and UI approval paths. |
| D7 | 2026-11-07 | LLM budget: per-run 300k tokens / $1.50; session bucket `stages-0-3` capped at **$7.00**, summed from the ledger across runs | Token-only caps; provider-side limits | The team asked for about $7 across Stages 0-3. A USD cap maps directly to that. It is checked before each call against a worst-case estimate. |
| D8 | 2026-11-07 | Prices for `claude-*-5-5` in config are conservative assumptions (Haiku $1/$5, Sonnet $3/$15, Opus $15/$75 per MTok) | Look up live prices | Published prices for these IDs were not verified. Overestimating means the real spend is at or below the reported cost, so the cap stays safe. |
| D9 | 2026-11-07 | `temperature` not sent to the API (`null` in config) | temperature 0 | The API returns 400 "`temperature` is deprecated for this model" for `claude-haiku-5-5`. Response caching gives the consistency instead. |
| D10 | 2026-11-07 | MLflow 2.19 with a local file store (`artifacts/mlruns`); `azureml-mlflow` only in `requirements-azure.txt` | sqlite backend; MLflow 3 | A file store needs no database. Keeping the Azure plugin out of the default install keeps CI light. |
| D11 | 2026-11-07 | Tests use `FakeBackend` (`LLM_PROVIDER=fake`); CI needs no secrets | Recorded real responses | Tests are free and deterministic. A real-API check is a separate manual command (`make llm-check`). |
| D12 | 2026-11-07 | Datasets: German Credit (scorecard), ULB credit-card fraud via public mirror, freMTPL2 claims (pricing GLM); SAS model is inventory and documentation only | Give Me Some Credit; Home Credit | German Credit is small and has age and sex/personal status for fairness tests. It has no date, so out-of-time testing uses a synthetic split (see limitations). No EXL sample code was supplied. |
| D13 | 2026-11-07 | Fixed splits are made once in Python (`factory.data`, seed 42) and saved to `data/processed/`. R and Python models read the same files. | Each model splits its own data | Parity (Stage 4) needs the R original and the Python rebuild to see exactly the same rows. One prep step also makes the splits auditable. |
| D14 | 2026-11-07 | Dataset mirrors: German Credit from UCI; ULB fraud from the TensorFlow public mirror (`creditcard.csv`); freMTPL2freq from the CASdatasets GitHub `.rda` (converted to CSV with R). Every file is checked by sha256. | OpenML ARFF mirrors; Kaggle | The OpenML downloads ran at about 60 KB/s and then stalled (40+ min for fraud). The other mirrors take seconds. Kaggle needs a login. |
| D15 | 2026-11-07 | Splits: German Credit 70/30 stratified random; fraud split by time (first 80% train / last 20% test); freMTPL2 80/20 random | Random for all | The fraud data has a time column, so a time split is a real out-of-time test. German Credit has no date (see limitations). |
| D16 | 2026-11-07 | Credit scorecard written in base R (manual WoE binning + `glm`), with no scorecard package | `scorecard` / `woeBinning` packages | Every transformation is visible in about 150 lines. That keeps the R→Python translation and its unit tests explainable, with no hidden package behaviour to reproduce. |
| D17 | 2026-11-07 | Pricing GLM in Python (statsmodels), not R | R `glm` | Only the scorecard has to be R. Keeping the pricing model in Python keeps the R surface small. The inventory still covers R, Python and SAS. |
| D18 | 2026-11-07 | Protected attributes (`sex`, `personal_status_sex`, `age_group`, `foreign_worker`) are excluded from the scorecard and kept for fairness tests. Age itself stays a model input. | Exclude age as well | Age is commonly used in UK credit scoring and has strong IV. Its fairness impact is measured in Stage 5 through `age_group`. |
| D19 | 2026-11-07 | Reference outputs committed under `artifacts/reference/<model>/`; datasets are not committed (`make data` re-downloads them) | Commit data | Small, versioned ground truth for parity and validation. No dataset copies in git. |
| D20 | 2026-11-07 | Code facts (libraries, inputs/outputs, methods, seeds, SAS librefs) come from a static scanner (`factory.scanner`: Python AST, regex for R and SAS), not the LLM | Ask the LLM to read the code | Deterministic, free and testable. The LLM only gets the scanner summary plus bounded file text (15k chars per file) and fills the fields that need reading comprehension. No data rows are sent. |
| D21 | 2026-11-07 | Inventory agent must quote evidence and its source file for every non-null value; quotes are checked against the file text and unsupported values are nulled and listed under `rejected_agent_answers` | Trust the LLM answer | Stops fabricated owners, dates or tiers reaching the inventory. The reviewer sees the quote next to each value at Gate 1. |
| D22 | 2026-11-07 | Gaps (documentation missing/outdated, validation overdue, missing owner/tier, non-executable language) are computed by fixed rules in `discover.assess_gaps`; thresholds in config (docs 24 months; revalidation high 12 / medium 24 / low 36 months) | Let the LLM judge gaps | Same inputs always give the same gaps. Only doc/code contradictions come from the LLM, and they are shown as findings for the reviewer to confirm. |
| D23 | 2026-11-07 | Risk tier is assigned by the LLM from a written rubric in config, with a rationale; left `unknown` if the material doesn't support it | Fixed rules on keywords | Tiering needs reading the business use. The rubric keeps it consistent and the reviewer can override at the gate. |
| D24 | 2026-11-07 | Extended thinking is turned off (`llm.thinking`) for extraction agents (scanner, inventory, monitor, healthcheck) | Raise `max_tokens` | The `claude-*-5-5` models think by default and thinking tokens count against `max_tokens`. On the first live run 3 of 4 inventory answers were cut off mid-JSON. With thinking off the same prompt used about 60% fewer output tokens and returned valid JSON. Reasoning-heavy agents (documentation, translation, report) keep the default. |
